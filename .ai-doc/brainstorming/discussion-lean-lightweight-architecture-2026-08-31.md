## Konteks

User menginginkan arsitektur sistem pengujian performa dan fungsional yang ringan (*lightweight*), tidak bergantung pada stack monitoring berat seperti Grafana/Prometheus atau multi-container database server (PostgreSQL/Redis), namun tetap tangguh dan siap pakai untuk lingkungan VPS dengan sumber daya terbatas.

---

## Ide yang Teridentifikasi & Keputusan

### 1. Dual-Layer Lightweight Reporting (Zero-Grafana)
* **Detail:** Menghapus container Grafana, Prometheus, dan daemon exporters. Menggantinya dengan CLI Progress Ticker secara realtime di terminal selama pengujian, dan meng-generate file statis `report.html` (interaktif) serta `summary.json` (metrik kuantitatif untuk CI/CD) setelah pengujian selesai.
* **Status:** `APPROVED`
* **Alasan:** Menghemat 400MB–700MB RAM, server kembali ke 0 MB ekstra konsumsi saat pengujian berakhir.

### 2. Zero-Infrastructure Storage & Queue (SQLite & In-Memory Queue)
* **Detail:** Menghilangkan ketergantungan pada PostgreSQL dan Redis. Menggunakan database file-based **SQLite** (`./data/test_history.db`) dengan WAL mode untuk pencatatan log hasil run, serta **In-Memory Queue** bawaan Node.js untuk dispatching job.
* **Status:** `APPROVED`
* **Alasan:** Zero external container dependencies, startup instan, setup super simpel.

### 3. Native Node.js / TypeScript Stack & Standalone Execution
* **Detail:** Tetap menggunakan Node.js/TypeScript karena Playwright adalah native di Node.js (di Go, `playwright-go` tetap men-spawn driver Node.js di background). Runner dikemas sebagai CLI tool mandiri dan 1 single Dockerfile tanpa kebutuhan `docker-compose`.
* **Status:** `APPROVED`
* **Alasan:** Ekosistem Playwright paling matang, tidak ada IPC bridging antar bahasa, dan concurrency dapat dibatasi secara cerdas agar aman dari OOM di VPS.
