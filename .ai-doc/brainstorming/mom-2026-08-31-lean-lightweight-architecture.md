## Ringkasan Diskusi

### 1. Observability & Reporting Ringan (Zero-Grafana)
- **Problem:** Grafana, Prometheus, dan exporter memakan RAM besar (~400MB–700MB) yang membebani VPS/host.
- **Keputusan:**
  - ✅ **Eliminasi Grafana & Prometheus.**
  - ✅ **Substitusi Live Stream:** Live Terminal CLI Progress Ticker (RPS, active workers, p95 latency, errors per detik).
  - ✅ **Substitusi Post-Run:** Menghasilkan single file `report.html` (visual grafik interaktif mandiri) dan `summary.json` (machine-readable data untuk CI/CD exit code).

### 2. Storage & Queue Hemat Resource
- **Problem:** PostgreSQL dan Redis menambah dependensi multi-container terpisah.
- **Keputusan:**
  - ✅ **Eliminasi PostgreSQL & Redis container.**
  - ✅ **Storage:** Gunakan **SQLite** (file `./data/test_history.db` via `better-sqlite3` dalam WAL mode).
  - ✅ **Queue:** Gunakan **In-Memory Worker Queue** bawaan runtime Node.js.
  - ✅ Sediakan abstraction interface (`TaskQueue` & `ResultStore`) agar tetap modular jika di masa depan ingin scale ke multi-machine.

### 3. Evaluasi Stack Bahasa: Node.js/TypeScript vs Go
- **Analisis:**
  - Playwright pada dasarnya native di Node.js. Di Go (`playwright-go`), binary Go tetap men-spawn driver Node.js di background via IPC untuk mengontrol browser.
  - Artillery adalah package berbasis Node.js.
- **Keputusan:**
  - ✅ **Tetap memilih Node.js / TypeScript** untuk menjaga satu ekosistem native Playwright yang matang, penulisan skenario yang fleksibel, dan zero IPC overhead.

### 4. Packaging & Execution Model
- **Keputusan:**
  - ✅ Standalone CLI command runner (`npm run test:run` / `test-runner run`).
  - ✅ Single Dockerfile mandiri (berbasis `mcr.microsoft.com/playwright`) tanpa `docker-compose`.
  - ✅ Dynamic concurrency safe-limit (mencegah browser headless memicu Out-of-Memory / OOM di VPS).
