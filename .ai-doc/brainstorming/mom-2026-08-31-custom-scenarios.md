## 1. Latar Belakang & Kebutuhan

Pengguna membutuhkan kemampuan untuk mengeksekusi skenario uji kustom (*custom scenario*) yang fleksibel melampaui sekadar single URL hit:
1. **Multi-Step HTTP API Chaining:** Login ➔ Ekstrak Token/Header ➔ Hit Protected Endpoint ➔ Assert Response.
2. **Browser Interaction Steps:** Buka Halaman ➔ Fill Form ➔ Klik Tombol ➔ Tunggu Selector ➔ Capture Screenshot Step ➔ Assert DOM Element.
3. **UI Dashboard yang Intuitif:** Mendukung Visual Step Builder (No-Code Form) serta Declarative JSON/YAML Editor dengan Preset Template.

## 2. Masukan & Perspektif Persona

### Melon 🏗️ (Technical Architect):
> *"Skenario kustom harus menggunakan struktur deklaratif terpadu (`ScenarioStepDefinition`). Satu runner engine yang bisa mengeksekusi langkah-langkah secara berurutan dengan konteks bersama (`ExecutionContext`). Dengan begitu, kita bisa mendukung HTTP Step dan Browser Action Step tanpa menduplikasi orkestrator."*

### Sultan ⚙️ (Senior Backend Engineer):
> *"Kunci utama di multi-step HTTP adalah **Variable Extraction & Context Propagation**. Jika Step 1 (POST `/login`) mengembalikan JSON `{ "token": "abc" }`, variabel `{{token}}` harus otomatis bisa disuntikkan ke Header `Authorization: Bearer {{token}}` pada Step 2. Selain itu, setiap step wajib punya timeout independen agar tidak menggantung runner."*

### Nindi 🔬 (QA & Diagnostician):
> *"Setiap step harus memiliki **Assertion Engine** yang tegas: cek HTTP Status (misal `200` atau `201`), JSON path assertion (`body.user.role == 'admin'`), atau CSS selector existence di browser. Jika sebuah step gagal, sistem harus mencatat detail error, log response/DOM, dan langsung mengambil screenshot bukti kegagalan."*

### Bernadya ✨ (Creative Visionary / UI):
> *"Dari sisi UI di Risograph Dashboard, kita buatkan panel **01B. Custom Scenario Builder**:*
> * *Toggle antara 'Quick URL Hit' dan 'Custom Scenario Mode'.*
> * *Visual Step Card list dengan tombol `+ Add Step` (pilihan action: `HTTP_REQUEST`, `GOTO`, `CLICK`, `FILL`, `ASSERT_TEXT`, `WAIT_SELECTOR`).*
> * *Tombol 'Load Preset Templates' (misal: 'JWT Auth Flow', 'E-Commerce Checkout', 'Form Login & Dashboard Inspect').*
> * *Tab Raw JSON/YAML untuk power user yang ingin copy-paste spec skenario."*

### Lugi 📊 (Data Specialist):
> *"Setiap step yang dieksekusi harus menghasilkan entri detail di SQLite tabel `test_executions`: `step_index`, `action_type`, `target`, `status`, `duration_ms`, `extracted_vars`, dan `error_message`. Jadi saat inspeksi riwayat di modal, user bisa melihat breakdown per-step secara terurut."*
